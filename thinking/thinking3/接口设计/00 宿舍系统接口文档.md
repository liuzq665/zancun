# 高校宿舍管理系统接口文档

| 项目 | 内容 |
| --- | --- |
| 文档版本 | v1.0 |
| 编制日期 | 2026-10-14 |
| 适用范围 | 学生、宿管、维修人员、系统管理员业务端 |
| 接口前缀 | `/api/v1` |

## 1. 接口约定

### 1.1 通用请求约定

- 除登录接口外，请求头使用 `Authorization: Bearer <token>`。
- JSON 请求使用 `Content-Type: application/json`。
- `BIGINT UNSIGNED` 主键在接口中使用 `string` 传输。
- 日期使用 `YYYY-MM-DD`；时间使用 `YYYY-MM-DDTHH:mm:ss.SSS+08:00`。
- 分页参数统一为 `page`（从 1 开始）和 `pageSize`（默认 20），分页结果包含 `page`、`pageSize`、`total`、`rows`。
- 所有接口均使用以下响应外壳：

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

失败响应使用相同外壳，`data` 为 `null`，例如：

```json
{
  "code": 40001,
  "message": "当前状态不允许此操作",
  "data": null
}
```

### 1.2 角色与权限边界

| 角色 | 权限边界 |
| --- | --- |
| 学生 | 本人账号、住宿信息、报修工单、留宿申请和消息 |
| 宿管 | 管辖楼栋内的住宿、报修和留宿业务 |
| 维修人员 | 本人被派工单、延期申请和维修记录 |
| 系统管理员 | 全校数据、账号、基础资料、业务规则及系统任务 |

系统管理员通过账号的 `ADMIN` 角色表达，不单独建立管理员资料接口。自动派单、自动锁定、自动确认和归档由系统内部任务执行，不作为第五个接口调用角色。

### 1.3 状态编码

- 报修工单：`DRAFT`、`PENDING_REVIEW`、`PENDING_EDIT`、`PENDING_ASSIGN`、`PENDING_ACCEPT`、`ACCEPTED`、`DELAYED`、`REPAIRED`、`CONFIRMED`、`PENDING_MANUAL`、`CLOSED`、`WITHDRAWN`、`ARCHIVED`。
- 留宿申请：`DRAFT`、`PENDING_REVIEW`、`UNDER_REVIEW`、`PENDING_EDIT`、`APPROVED`、`COMPLETED`、`ARCHIVED`。
- 异步任务：`WAITING`、`RUNNING`、`SUCCESS`、`PARTIAL`、`FAILED`、`CANCELLED`。
- 派单记录：`PENDING`、`ACCEPTED`、`REJECTED`、`TIMEOUT`、`CANCELLED`。

下文每个接口均按“基本信息、请求参数、响应数据”三部分描述。

## 2. 认证与个人信息接口

### 2.1 用户登录

#### 基本信息

请求路径：`/api/v1/auth/login`

请求方式：`POST`

接口描述：四类角色使用账号和密码登录，成功后返回访问令牌及当前角色信息。

#### 请求参数

参数格式：`application/json`

参数说明：

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `loginAccount` | string | 是 | 登录账号 |
| `password` | string | 是 | 登录密码 |

请求参数样例：

```json
{"loginAccount":"20260001","password":"Password@123"}
```

#### 响应数据

参数格式：`application/json`

参数说明：`data.token` 为访问令牌；`data.user` 为当前账号基本资料；`data.roles` 为当前有效角色。

响应数据样例：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiJ9.example",
    "expiresAt": "2026-10-14T23:59:59.000+08:00",
    "user": {"userId":"10001","loginAccount":"20260001","realName":"张三","phone":"13800000000","roleCode":"STUDENT"},
    "roles": ["STUDENT"]
  }
}
```

### 2.2 退出登录

#### 基本信息

请求路径：`/api/v1/auth/logout`

请求方式：`POST`

接口描述：使当前访问令牌失效并结束当前登录会话。

#### 请求参数

参数格式：无请求体，使用认证请求头。

参数说明：无。

请求参数样例：无。

#### 响应数据

参数格式：`application/json`

参数说明：`data` 为空对象。

响应数据样例：

```json
{"code":0,"message":"success","data":{}}
```

### 2.3 查询当前用户

#### 基本信息

请求路径：`/api/v1/me`

请求方式：`GET`

接口描述：查询当前登录用户的账号、角色和角色资料。

#### 请求参数

参数格式：无请求体，使用认证请求头。

参数说明：无。

请求参数样例：无。

#### 响应数据

参数格式：`application/json`

参数说明：返回当前用户；仅返回当前账号拥有的角色资料。

响应数据样例：

```json
{
  "code":0,"message":"success","data":{
    "userId":"10001","loginAccount":"20260001","realName":"张三","phone":"13800000000","email":"zhangsan@example.edu.cn","roles":["STUDENT"],
    "studentProfile":{"studentProfileId":"30001","studentNo":"20260001","classId":"20001","enrollmentStatus":"ENROLLED"}
  }
}
```

### 2.4 修改个人信息

#### 基本信息

请求路径：`/api/v1/me/profile`

请求方式：`PUT`

接口描述：当前用户修改允许维护的联系方式和个人资料，不修改账号、角色和业务归属。

#### 请求参数

参数格式：`application/json`

参数说明：`phone`、`email`、`gender` 均可修改。

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `phone` | string | 否 | 联系电话 |
| `email` | string | 否 | 邮箱 |
| `gender` | string | 否 | 性别 |

请求参数样例：

```json
{"phone":"13900000000","email":"new@example.edu.cn","gender":"男"}
```

#### 响应数据

参数格式：`application/json`

参数说明：返回修改后的个人资料。

响应数据样例：

```json
{"code":0,"message":"success","data":{"userId":"10001","realName":"张三","phone":"13900000000","email":"new@example.edu.cn","gender":"男"}}
```

### 2.5 修改密码

#### 基本信息

请求路径：`/api/v1/me/password`

请求方式：`PUT`

接口描述：当前用户校验原密码后修改登录密码。

#### 请求参数

参数格式：`application/json`

参数说明：

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `oldPassword` | string | 是 | 原密码 |
| `newPassword` | string | 是 | 新密码 |

请求参数样例：

```json
{"oldPassword":"Password@123","newPassword":"NewPassword@123"}
```

#### 响应数据

参数格式：`application/json`

参数说明：不返回密码，仅返回操作结果。

响应数据样例：

```json
{"code":0,"message":"success","data":{}}
```

## 3. 文件与消息接口

### 3.1 上传业务附件

#### 基本信息

请求路径：`/api/v1/files`

请求方式：`POST`

接口描述：上传报修或其他业务允许使用的附件，返回文件标识；业务提交接口只保存已上传文件的 `fileId`。

#### 请求参数

参数格式：`multipart/form-data`

参数说明：

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `file` | file | 是 | 附件文件 |
| `businessType` | string | 是 | `REPAIR_ORDER` 或 `REPAIR_RESULT` |

请求参数样例：`file=repair.jpg&businessType=REPAIR_ORDER`。

#### 响应数据

参数格式：`application/json`

参数说明：`url` 根据存储配置由系统生成，不作为业务基本项回写业务表。

响应数据样例：

```json
{"code":0,"message":"success","data":{"fileId":"80001","originalName":"水龙头漏水.jpg","fileType":"image/jpeg","byteSize":245760,"url":"/api/v1/files/80001/content"}}
```

### 3.2 查询本人消息

#### 基本信息

请求路径：`/api/v1/messages`

请求方式：`GET`

接口描述：查询当前用户收到的站内消息，支持按已读状态和消息类型分页。

#### 请求参数

参数格式：`query string`

参数说明：

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `page` | integer | 否 | 页码，默认 1 |
| `pageSize` | integer | 否 | 页大小，默认 20 |
| `readStatus` | string | 否 | `UNREAD` 或 `READ` |
| `messageType` | string | 否 | 消息类型 |

请求参数样例：`?page=1&pageSize=20&readStatus=UNREAD`。

#### 响应数据

参数格式：`application/json`

参数说明：`readAt` 为 `null` 表示未读；`rows` 只返回当前用户的接收记录。

响应数据样例：

```json
{"code":0,"message":"success","data":{"page":1,"pageSize":20,"total":1,"rows":[{"messageId":"90001","title":"报修审核通过","body":"报修单 RE202610140001 已通过审核","messageType":"REPAIR_STATUS","readAt":null,"createdAt":"2026-10-14T10:20:00.000+08:00"}]}}
```

### 3.3 查看消息并标记已读

#### 基本信息

请求路径：`/api/v1/messages/{messageId}`

请求方式：`GET`

接口描述：查看当前用户的一条消息，并在首次查看时写入该用户的已读时间。

#### 请求参数

参数格式：`path variable`

参数说明：`messageId` 为消息标识，必须属于当前用户的接收记录。

请求参数样例：`GET /api/v1/messages/90001`。

#### 响应数据

参数格式：`application/json`

参数说明：返回消息正文及业务关联标识。

响应数据样例：

```json
{"code":0,"message":"success","data":{"messageId":"90001","title":"报修审核通过","body":"报修单 RE202610140001 已通过审核","businessType":"REPAIR_ORDER","businessId":"70001","readAt":"2026-10-14T10:25:00.000+08:00"}}
```

### 3.4 发布站内消息

#### 基本信息

请求路径：`/api/v1/messages`

请求方式：`POST`

接口描述：宿管向管辖楼栋范围发布消息，系统管理员向全校或指定范围发布消息。

#### 请求参数

参数格式：`application/json`

参数说明：

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `title` | string | 是 | 标题 |
| `body` | string | 是 | 正文 |
| `messageType` | string | 是 | 消息类型 |
| `receiverScope` | object | 是 | 接收范围；包含 `scopeType` 和对应范围标识 |

请求参数样例：

```json
{"title":"宿舍检查通知","body":"本周五进行宿舍安全检查。","messageType":"NOTICE","receiverScope":{"scopeType":"BUILDING","buildingIds":["101"]}}
```

#### 响应数据

参数格式：`application/json`

参数说明：消息发布后生成接收记录；`messageId` 为消息标识。

响应数据样例：

```json
{"code":0,"message":"success","data":{"messageId":"90002","title":"宿舍检查通知","createdAt":"2026-10-14T11:00:00.000+08:00"}}
```

## 4. 住宿信息接口

### 4.1 查询当前住宿信息

#### 基本信息

请求路径：`/api/v1/accommodations/current`

请求方式：`GET`

接口描述：学生查询本人当前有效或已生效的楼栋、宿舍和床位；宿管和系统管理员可按权限查询指定学生。

#### 请求参数

参数格式：`query string`

参数说明：学生不传 `studentProfileId`；宿管或管理员查询指定学生时传入该参数。

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `studentProfileId` | string | 否 | 学生资料标识 |
|
请求参数样例：`GET /api/v1/accommodations/current`。

#### 响应数据

参数格式：`application/json`

参数说明：住宿状态和床位占用根据住宿关系有效日期推导，不重复存储统计值。

响应数据样例：

```json
{"code":0,"message":"success","data":{"assignmentId":"50001","studentProfileId":"30001","buildingId":"101","buildingName":"一号楼","roomId":"1001","roomNo":"101","bedId":"40001","bedNo":"01","startDate":"2026-09-01","endDate":null,"status":"ACTIVE"}}
```

### 4.2 查询楼栋、宿舍和床位

#### 基本信息

请求路径：`/api/v1/dormitories`

请求方式：`GET`

接口描述：宿管查询管辖楼栋的宿舍和床位，系统管理员查询全校住宿基础资料，并可按状态筛选床位。

#### 请求参数

参数格式：`query string`

参数说明：

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `buildingId` | string | 否 | 楼栋标识 |
| `roomId` | string | 否 | 宿舍标识 |
| `managementStatus` | string | 否 | 床位状态 |
| `page` | integer | 否 | 页码 |
| `pageSize` | integer | 否 | 页大小 |

请求参数样例：`?buildingId=101&bedStatus=AVAILABLE&page=1&pageSize=20`。

#### 响应数据

参数格式：`application/json`

参数说明：返回基础楼栋、宿舍、床位资料和当前占用情况。

响应数据样例：

```json
{"code":0,"message":"success","data":{"page":1,"pageSize":20,"total":1,"rows":[{"buildingId":"101","buildingName":"一号楼","roomId":"1001","roomNo":"101","capacity":4,"beds":[{"bedId":"40001","bedNo":"01","bedStatus":"AVAILABLE"}]}]}}
```

### 4.3 分配学生住宿

#### 基本信息

请求路径：`/api/v1/accommodations`

请求方式：`POST`

接口描述：宿管或系统管理员为学生分配床位；系统按有效日期检查学生和床位的时间区间冲突。

#### 请求参数

参数格式：`application/json`

参数说明：

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `studentProfileId` | string | 是 | 学生资料标识 |
| `bedId` | string | 是 | 床位标识 |
| `startDate` | date | 是 | 入住开始日期 |
| `endDate` | date | 否 | 结束日期，长期住宿为空 |
| `remark` | string | 否 | 分配说明 |

请求参数样例：

```json
{"studentProfileId":"30001","bedId":"40001","startDate":"2026-09-01","endDate":null,"remark":"秋季学期分配"}
```

#### 响应数据

参数格式：`application/json`

参数说明：返回新建住宿关系；`status` 为 `PENDING` 或 `ACTIVE`，由生效日期推导。

响应数据样例：

```json
{"code":0,"message":"success","data":{"assignmentId":"50002","studentProfileId":"30001","bedId":"40001","startDate":"2026-09-01","endDate":null,"status":"ACTIVE"}}
```

### 4.4 结束住宿分配

#### 基本信息

请求路径：`/api/v1/accommodations/{accommodationId}/end`

请求方式：`POST`

接口描述：宿管或系统管理员结束一条有效住宿关系，释放其在结束日期后的床位占用。

#### 请求参数

参数格式：`application/json`

参数说明：

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `endDate` | date | 是 | 实际结束日期 |
| `reason` | string | 是 | 结束原因 |

请求参数样例：

```json
{"endDate":"2027-01-20","reason":"学生退宿"}
```

#### 响应数据

参数格式：`application/json`

参数说明：返回更新后的住宿关系。

响应数据样例：

```json
{"code":0,"message":"success","data":{"assignmentId":"50002","endDate":"2027-01-20","status":"ENDED"}}
```
## 5. 报修业务接口

### 5.1 新建报修草稿

#### 基本信息

请求路径：`/api/v1/repair-orders`

请求方式：`POST`

接口描述：学生创建本人报修草稿；草稿尚未进入宿管审核，可继续修改。

#### 请求参数

参数格式：`application/json`

参数说明：

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `roomId` | string | 是 | 报修宿舍标识，必须属于学生当前住宿范围 |
| `categoryId` | string | 是 | 故障分类标识 |
| `workTypeId` | string | 是 | 维修工种标识 |
| `specificLocation` | string | 否 | 故障具体位置 |
| `faultDescription` | string | 是 | 故障描述 |
| `studentRemark` | string | 否 | 学生补充说明 |
| `fileIds` | string[] | 否 | 已上传附件标识列表 |

请求参数样例：

```json
{"roomId":"1001","categoryId":"501","workTypeId":"601","specificLocation":"卫生间","faultDescription":"水龙头漏水","fileIds":["80001"]}
```

#### 响应数据

参数格式：`application/json`

参数说明：新建工单初始状态为 `DRAFT`；`orderNo` 为业务工单号。

响应数据样例：

```json
{"code":0,"message":"success","data":{"orderId":"70001","orderNo":"RE202610140001","currentStatus":"DRAFT","createdAt":"2026-10-14T12:00:00.000+08:00"}}
```

### 5.2 修改报修草稿

#### 基本信息

请求路径：`/api/v1/repair-orders/{orderId}`

请求方式：`PUT`

接口描述：学生修改本人处于 `DRAFT` 或 `PENDING_EDIT` 状态的报修内容。

#### 请求参数

参数格式：`application/json`

参数说明：字段规则与新建报修草稿一致；修改 `PENDING_EDIT` 工单时覆盖当前待修改版本内容。

请求参数样例：

```json
{"specificLocation":"卫生间","categoryId":"501","workTypeId":"601","faultDescription":"水龙头接口持续漏水","studentRemark":"请尽快处理","fileIds":["80001","80002"]}
```

#### 响应数据

参数格式：`application/json`

参数说明：返回更新后的工单内容和当前状态，状态仍保持 `DRAFT` 或 `PENDING_EDIT`。

响应数据样例：

```json
{"code":0,"message":"success","data":{"orderId":"70001","orderNo":"RE202610140001","currentStatus":"DRAFT","versionId":"71001","updatedAt":"2026-10-14T12:05:00.000+08:00"}}
```

### 5.3 提交报修工单

#### 基本信息

请求路径：`/api/v1/repair-orders/{orderId}/submit`

请求方式：`POST`

接口描述：学生提交本人报修草稿或待修改工单，系统校验必填信息后进入宿管审核。

#### 请求参数

参数格式：无请求体，使用认证请求头。

参数说明：`orderId` 必须属于当前用户，且当前状态为 `DRAFT` 或 `PENDING_EDIT`。

请求参数样例：`POST /api/v1/repair-orders/70001/submit`。

#### 响应数据

参数格式：`application/json`

参数说明：提交成功后状态为 `PENDING_REVIEW`，并产生一条提交版本。

响应数据样例：

```json
{"code":0,"message":"success","data":{"orderId":"70001","versionId":"71002","currentStatus":"PENDING_REVIEW","submittedAt":"2026-10-14T12:10:00.000+08:00"}}
```

### 5.4 查询报修工单列表

#### 基本信息

请求路径：`/api/v1/repair-orders`

请求方式：`GET`

接口描述：学生查询本人报修；宿管查询管辖楼栋报修；维修人员查询本人派单；管理员查询全校报修。

#### 请求参数

参数格式：`query string`

参数说明：

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `page` | integer | 否 | 页码 |
| `pageSize` | integer | 否 | 页大小 |
| `currentStatus` | string | 否 | 报修工单当前状态 |
| `orderNo` | string | 否 | 工单号 |
| `buildingId` | string | 否 | 楼栋标识；按角色校验范围 |
| `categoryId` | string | 否 | 故障分类 |
| `startDate` | date | 否 | 创建日期起 |
| `endDate` | date | 否 | 创建日期止 |

请求参数样例：`?page=1&pageSize=20&currentStatus=PENDING_REVIEW&buildingId=101`。

#### 响应数据

参数格式：`application/json`

参数说明：返回按权限过滤后的工单摘要和派单摘要；统计字段从视图查询，不写回工单基础表。

响应数据样例：


## 8. 业务事务与接口约束

1. 创建、修改、提交、审核、派单、接单、维修结果提交、确认、评价和重修必须校验当前对象状态及调用者的数据范围，并在一次业务操作中保存对应事实记录和状态变化。
2. 自动派单、派单超时、留宿自动锁定、待修改逾期处理、维修超时、维修后超时自动确认以及留宿完成归档由系统任务执行；不提供由客户端直接更改这些结果状态的接口。
3. 留宿申请的每次提交产生版本；审核记录关联具体版本。`applicationSource` 是来源事实，不是状态。
4. 报修强制派单直接产生已接受派单和 `ACCEPTED` 工单状态；普通自动派单才会产生等待维修人员决定的派单。
5. 查询统计和派生展示字段从数据库视图或查询计算获得，不作为冗余基本项写回业务表。
6. `202` 或 `WAITING` 只代表异步任务受理；任务最终结果必须通过任务查询接口获取。
